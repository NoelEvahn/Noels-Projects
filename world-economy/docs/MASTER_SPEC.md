## 1. Product definition

| Item | Requirement |
|---|---|
| Genre | 3D open-world life and business simulation, single player, browser |
| Start | Exactly $100.00 cash, no assets, no job, arriving in Harlan City Old Town |
| Arc | Jobs → savings → first small business → vehicles and property → multiple businesses with staff → empire |
| Most important system | Business and entrepreneurship (Annex D) |
| Look | Closest achievable approximation of the 15 reference images (Annex A). Premium, not a prototype |
| Deliverables | (1) `dist/life.html`, one self-contained file that runs offline from `file://`. (2) The same game as a Claude Artifact (single-file publish, and a multi-file layout `dist/artifact/`) |
| Assets | All textures generated by our code at runtime. All audio synthesised with WebAudio at runtime. No downloaded images, models or samples |
| Performance | Stable 60 fps on the reference desktop mid-range GPU at the High preset (Annex G). Hard requirement |
| Platforms | Desktop Chromium/Firefox/Safari with WebGL2. Layout works from 768 px width up. Keyboard and mouse primary; gamepad and basic touch are P2 |

### 1.1 Honest fidelity statement

The references are offline renders or Unreal-class captures: ray-traced or Lumen GI, Nanite geometry, megascans, 4K–8K textures, volumetric fog, photogrammetry people. A browser WebGL2 forward renderer with code-generated assets cannot match that. The target is: **a coherent, physically based, well-lit, atmospheric world that reads as "high-end stylised realism" at gameplay camera distance**, comparable to a good 2014–2016 console open-world title at medium distance, weaker on characters and on close-up surface detail. Annex A section 2 lists, per reference, what is reproduced and what is approximated.

## 3. Architecture decision

### 3.1 Decision summary

| Topic | Decision | Reason |
|---|---|---|
| Engine | **three.js `0.180.0`** (exact pin), WebGL2 `WebGLRenderer` | 0.33 MB core, the most LLM-familiar engine, complete addon set (CSM, GTAO, bloom, SMAA, Reflector), proven in the probe. Babylon.js is 5 MB core, less familiar to the implementing models, and its extras (Havok, node materials) are not needed |
| Graphics API | WebGL2 only | WebGPU cannot be tested here, is uneven across browsers, and the TSL/WebGPU path in three is a different material system. No fallback to WebGL1 |
| Library delivery | three and addons are **bundled inline** by esbuild. No runtime CDN script | The single file must run offline. The CDN rule (cdnjs, pinned version) therefore never applies. If a CDN copy is ever wanted: `https://cdnjs.cloudflare.com/ajax/libs/three.js/0.180.0/three.module.min.js` (published 2025-09-03, present on cdnjs) |
| Physics | **Own code** in `src/game/physics/`: capsule character controller, raycast vehicle, buoyancy boat, 2.5D OBB/cylinder colliders on a spatial hash | Rapier is 2 MB of WASM and WASM instantiation inside the artifact CSP is unverified. Own physics is deterministic, runs headless in Node for tests, and the world is heightfield + boxes |
| Audio | Direct WebAudio, own synth and mixer. No Tone.js, no AudioWorklet | All sound is bespoke synthesis; Tone.js adds weight without solving it. AudioWorklet fails from `blob:` (verified) |
| Textures | Runtime **GPU-baked** PBR sets (GLSL → render targets) plus Canvas2D for typography and signage | Milliseconds per map on a GPU, zero file bytes, re-bakeable on quality change, LRU-evictable |
| Geometry | 100% code-generated parametric kits (Annex A section 6). No GLB | No DCC tool exists here, and assets must be made by us |
| UI | DOM + CSS overlay, vanilla JS with a 2 KB helper (`ui/kit`). No framework | Small, familiar, easy to bind to the sim |
| Build | ES modules in `src/`, **esbuild** `0.25.10` bundles to `dist/life.html` (everything inline) and `dist/artifact/` (multi-file) | No-build importmaps would need CDN access and many requests. One bundler step gives both deliverables |
| Language | JavaScript (ES2022) with JSDoc typedefs in `src/core/contracts.js`. No TypeScript compile step | Fewer moving parts; `tsc --checkJs` MAY be run as a lint |
| Simulation | Pure JS, no three/DOM imports in `src/core`, `src/data`, `src/sim`, `src/world`, `src/game` | The whole economy and all job logic run in Node for tests and balance bots |

Build rules:

## 4. Runtime model

### 4.1 Boot sequence (`src/main.js`)

1. Create `bus`, `settings` (defaults + stored), `Sim` (new game state or save), `World` (layout + height grid, time-sliced).
2. Show main menu immediately (DOM). Start world generation behind it.
3. Create renderer, run the quality auto-benchmark if `graphics.preset === 'auto'` (Annex G section 3.4).
4. Bake the boot texture set (Annex A section 5.5), build far proxies, build chunks around the camera.
5. Prewarm shader programs with `renderer.compileAsync(scene, camera)`.
6. Menu shows "Continue / New Game" enabled. The click that starts the game also resumes the `AudioContext` and requests pointer lock (both inside the click handler, both with refusal handling).
7. Main loop starts.

### 4.2 Main loop

```
frame(now):
  dtReal = clamp(now - last, 0, 100 ms)
  Input.poll()
  acc += dtReal;  steps = 0
  while (acc >= 1/60 s && steps < 4):          // fixed step
     Game.fixedUpdate(1/60)                    // physics, player, vehicles, AI, job controllers
     Clock.advance(1/60 s real)                // emits time:minute etc.; Sim ticks inside
     acc -= 1/60;  steps++
  if (steps == 4) acc = 0                      // drop time, never spiral
  Game.update(dtReal, alpha = acc * 60)        // interpolation state, camera rig
  Streaming.pump(budgetMs)                     // chunk build, bakes, pooled spawns (time-sliced)
  Render.frame(alpha)                          // entity views, culling, passes
  Audio.update(dtReal);  UI.update(dtReal);  Perf.endFrame();  Governor.update()
```

### 4.3 Time model

| Quantity | Value |
|---|---|
| Time scale | 1 real second = 1 game minute (scale 1). A day is 24 real minutes |
| Start | Day 1, 08:00, Monday, clear weather |
| Calendar | 7-day week (`mon`…`sun`), 4-week month. Day index starts at 1 |
| Economy tick | `time:minute` every game minute; `time:hour` hourly (business simulation, market update); `time:day` at 00:00 (rent, wages settle, spoilage, reports); `time:week` Monday 00:00 (tax, loan interest) |
| Sleep / wait | Sets clock scale to 120 (2 game hours per real second) with rendering reduced to a fade screen; the sim runs the same hourly functions |
| Pause | Menu and phone do not pause by default; `Esc` menu pauses (scale 0) |
| No offline progress | Closing the tab stops time |

All randomness comes from `core/rng.js` streams stored in the save (section 8). `Math.random` MUST NOT be used in `core/`, `sim/`, `world/`, `game/` (cosmetic-only use is allowed in `render/`, `art/`, `audio/`).

## 5. Public interfaces (binding contracts)

All typedefs live in `src/core/contracts.js`. Stage 2 creates these modules with working minimal implementations so later stages build against real code.

### 5.1 Common types

```js
/** @typedef {number} Cents      integer, never fractional. $1 = 100 */
/** @typedef {[number, number, number]} Vec3   [x, y, z] metres */
/** @typedef {{ok:true, data?:any} | {ok:false, error:string, detail?:any}} Result */
/** @typedef {{day:number, minute:number, total:number}} GameTime   // minute 0..1439, total = minutes since Day 1 00:00 */
```

Axes: +X east, +Y up, +Z south. North is −Z. Yaw 0 faces −Z (north), positive yaw turns toward +X (east). Units: metres, seconds, kilograms, radians.

### 5.2 EventBus (`core/bus.js`)

```js
bus.on(type, handler)        // → unsubscribe():void
bus.once(type, handler)      // → unsubscribe():void
bus.emit(type, payload)      // synchronous; a throwing handler is caught, logged, and does not stop others
bus.defer(type, payload)     // queued, flushed at the end of the current fixedUpdate
```

Event names are `domain:action`. Payloads are plain JSON-serialisable objects. The full list is section 7.6. Handlers MUST NOT mutate payloads.

### 5.3 Sim facade (`sim/index.js`) — the only way to change or read economic state

```js
Sim.init({ state?: SaveV1['sim'], seed?: number })   // new game when state is absent
Sim.tickMinute(gameTime)                             // called by Clock; fans out to hour/day/week
Sim.cmd(name, args)        // → Result.  All mutations. Table: Annex D section 12
Sim.select(name, args?)    // → plain data snapshot (never a live reference). Table: Annex D section 13
Sim.serialize()            // → SaveV1['sim']
Sim.ledger                 // Ledger API below (read methods are public; transfer is used by sim modules only)
```

Rules:
- UI and `game/` MUST use `Sim.cmd` / `Sim.select`. They MUST NOT import `sim/*` modules other than `sim/index.js`.
- Every command validates its arguments and returns `{ok:false,error}` with an error code from `data/ids.js` (`ERR.*`) instead of throwing.
- Every command that moves money does it through `Ledger.transfer`. There is no other money variable anywhere.

### 5.4 Ledger API (`sim/ledger.js`) — single source of truth for money

```js
Ledger.openAccount(id, { kind, owner, overdraft?: Cents })   // kind: 'cash'|'bank'|'business'|'loan'|'external'
Ledger.closeAccount(id)                                      // balance must be 0
Ledger.balance(id)                                           // → Cents
Ledger.canAfford(id, amount)                                 // → boolean
Ledger.transfer({ from, to, amount, type, memo?, ref? })     // → Result<{tx}>
Ledger.charge({ amount, to, type, memo?, ref?, method? })    // player pays; method 'auto'|'cash'|'card'
Ledger.query({ account?, type?, fromDay?, toDay?, limit? })  // → Tx[] newest first
Ledger.totals({ account, fromDay, toDay })                   // → { [type]: {in:Cents, out:Cents} }
Ledger.checkInvariant()                                      // → {ok:boolean, sum:Cents}   sum of all balances must be 0
```

```js
/** @typedef {Object} Tx
 *  @property {number} id        monotonically increasing
 *  @property {number} t         GameTime.total (minutes)
 *  @property {string} from      account id
 *  @property {string} to        account id
 *  @property {Cents}  amount    > 0
 *  @property {string} type      TX.* (section 7.4)
 *  @property {string} [memo]
 *  @property {string} [ref]     id of the job shift, business, property, vehicle …
 */
```

Rules: double entry (every transfer debits one account and credits another); `amount` is a positive integer; a transfer fails with `ERR.INSUFFICIENT_FUNDS` if `balance(from) - amount < -overdraft`; external accounts (`ext:*`) have unlimited overdraft and represent the outside world; the journal keeps the last 5,000 transactions plus per-day per-account per-type totals for 56 days (all reports derive from these). `Ledger.charge` with `method:'auto'` uses `cash` if it covers the whole amount, else `bank:checking`, else fails (it never splits). Details and account list: Annex D section 1.

```js
/** @typedef {Object} Archetype
 *  @property {string} id @property {string} category   'building'|'prop'|'vegetation'|'vehicle'|'boat'|'character'|'animal'|'interior'|'piece'
 *  @property {Vec3} size                        bounding box w,h,d
 *  @property {Collider[]} colliders             local space
 *  @property {Anchor[]} anchors                 doors, counters, seats, parking, interact points (local space)
 *  @property {number[]} lod                     switch distances [lod0→1, lod1→2, cull]
 *  @property {Object} [paramSchema]
 */
/** @typedef {Object} Collider   shape 'box'|'cyl'|'deck'|'ramp'; pos:Vec3; half:Vec3 | radius,height; rotY; yMin; yMax; walkable:boolean; surface?:string */
/** @typedef {Object} Poi        id; type; name; region; district; pos:Vec3; rotY; placementId?; tags:string[]; data?:Object */
/** @typedef {Object} Interactable  id; kind (INT.*); pos:Vec3; radius; prompt (string key); poiId?; placementId?; data? */
```

**Builder registry contract** (`render/builders.js`): the world is data; meshes are produced by builders keyed by archetype id.

```js
Builders.register(archetypeId, builder, { stage })   // a later registration replaces an earlier one
/** builder(placementOrParams, ctx) → BuildResult
 *  ctx = { lod:0|1|2, matlib, rng, quality, kit }
 *  BuildResult = { batches: [{ geometry, materialId, instanceMatrices? }], lights?: LightDef[], emissiveWindows?: … }
 *  Builders return raw geometry + material ids. They never add to the scene; ChunkManager merges and instances. */
```

Stage 2 registers a blockout builder for **every** archetype (`src/blockout/`). Stage 3 registers detailed builders under the same ids (`src/art/`). Placement data, colliders and anchors do not change between the two, so gameplay is unaffected by which builder is active. `settings.debug.blockout = true` forces blockout builders.

### 9.1 Ownership model

A directory has one owning stage at a time. A later stage may edit a file owned by an earlier stage only to (a) fix a bug, or (b) add an integration hook, and MUST record it in `docs/DECISIONS.md`. Contract files are frozen after tag `s2a-scaffold`: `src/core/contracts.js`, `src/data/ids.js`, and the signatures in section 5. A contract change needs an entry "CONTRACT CHANGE" in `docs/DECISIONS.md` and updates to every caller in the same commit.

| Path | S2 | S3 | S4 | S5 | S6 |
|---|---|---|---|---|---|
| `build.mjs`, `package.json` | owner | edit hooks | edit hooks | edit hooks | owner |
| `src/core/**`, `src/data/ids.js` | owner | read | bugfix | read | bugfix |
| `src/world/**` | owner | add `anchors`, light defs, decoration placements | add interactables, sites | read | tune |
| `src/blockout/**` | owner | read | read | read | read |
| `src/render/**` | minimal versions | **owner** | read | read | tune |
| `src/art/**` | — | **owner** | read | read | add detail |
| `src/audio/**` | stub (`engine.js` no-op API) | **owner** (engine, ambience, music, core SFX) | call by id only | call by id only | add remaining SFX patches |
| `src/data/*.js` (balance, items …) | create stubs from Annex D | read | **owner** | read | tune |
| `src/sim/**` | `ledger.js`, `index.js` skeleton | read | **owner** | read | bugfix |
| `src/game/**` | player, camera, input, physics (basic) | may add camera/FX hooks | **owner** | read | tune |
| `src/ui/**` | debug HUD only (`ui/hud/debugHud.js`) | perf HUD (`ui/hud/perfHud.js`) | job HUD placeholders in `ui/hud/jobDev.js` | **owner** | polish |
| `src/qa/**`, `test/**` | owner of harness; each stage adds its own tests | adds visual + perf tests | adds unit + sim tests | adds UI e2e | all |

### 9.3 Stage 3 — Visual production (Opus)

**Scope:** renderer pipeline, quality system and governor, perf HUD, MatLib and texture library, sky/lighting/fog/weather visuals, water, detailed builders for all archetypes (buildings, props, vegetation, vehicles, boats, characters, animals, interiors), particles and decals, night lighting, audio engine with ambience, music and core SFX.

**Optimisation is part of this stage's definition of done, not a later pass.** The Stage 3 brief MUST include these mandates:

| # | Mandate |
|---|---|
| O1 | Static world geometry is merged per chunk per material, or instanced (`InstancedMesh`) per archetype part. No per-object meshes for static props |
| O2 | Every archetype has an LOD chain (LOD0, LOD1, LOD2 or impostor) with the switch distances in `archetypes.js`, scaled by `lodBias` |
| O3 | Materials come only from `MatLib.get(id, variant)`. Target ≤ 60 unique material programs in memory; ≤ 40 visible in one view |
| O4 | Texture sizes obey the caps of the active preset (Annex G §3.3). Signage, decals, plates, UI-in-world use shared atlases |
| O5 | Procedural textures are baked at startup or on region approach, time-sliced (≤ 1 bake per frame during play), with the boot set inside the startup budget |
| O6 | Frustum culling on every batch (correct bounding spheres for instanced batches, per chunk). Occlusion: chunk-level horizon/portal test for city blocks and interior/exterior separation (Annex G §4.4) |
| O7 | Shadow casters limited per cascade (Annex G §2.3); small props and far LODs do not cast |
| O8 | Shader cost limits: world materials are `MeshStandardMaterial` + the shared patch set. No per-pixel loops over lights beyond the light pool. Post passes run at the resolutions in Annex A §3 |
| O9 | Pooling: entity views, particles, decals, audio voices, temporary vectors. No allocation in per-frame code paths |
| O10 | No shader compilation during gameplay after prewarm (program count constant; asserted) |
| O11 | Per-region budgets for draw calls, triangles, texture memory, geometry memory MUST be measured at the standard viewpoints and written to `docs/PERF_REPORT.md` using the template in Annex G §8 before hand-off |
| O12 | Quality presets and every toggle in Annex G §3 work at runtime; the governor drops effects before frames |

**Outputs:** `src/render/**`, `src/art/**`, `src/audio/**`, `ui/hud/perfHud.js`, `test/visual/*`, `test/perf/*`, `test/audio/*`, `docs/PERF_REPORT.md`.

Acceptance:
1. Detailed builder registered for 100% of archetypes; blockout fallback count = 0 in a full-world scan (`__LOE.perf.snapshot().blockoutFallbacks === 0`).
2. Texture library: every `tex.*` set in Annex A §5.3 bakes without GL error; test reads back the centre and edge texels of each map and asserts tileability (wrap seam difference below threshold) and non-flatness (variance above threshold).
3. Counter budgets (Annex G §2.3) hold at all 16 standard viewpoints for presets Low, Medium, High, Ultra: draw calls, triangles, shadow-caster draws, texture bytes, geometry bytes, program count. Enforced by `test/perf/perf.spec.cjs`.
4. JS frame cost measured in headless (no GL time): render submission + culling + animation ≤ 5 ms mean at High at every standard viewpoint; streaming overruns = 0 on the ring fly-through; steady-state allocation ≤ 50 KB per frame (measured over 600 frames with `performance.memory` where available).
5. Program count does not change during a 60 s scripted traverse after prewarm.
6. Perf HUD (F3) shows fps, frame ms (avg, p95, p99, max), CPU breakdown, draw calls, triangles, texture MB, geometry MB, programs, heap, entity counts, resolution scale, governor level.
7. Governor unit test with synthetic frame times: steps down in the specified order, restores with hysteresis, never changes a setting the user set explicitly to a lower value.
8. Screenshot set: 16 viewpoints × {08:00 clear, 18:30 golden hour, 22:00 night} + 6 weather shots at High, 960×540. Visual checklist Annex G §7.3 completed in `docs/PERF_REPORT.md` with pass/fail per row.
9. Audio: every `amb.*`, `mus.*` and P0 `sfx.*`/`eng.*` id renders offline with RMS in its specified range, peak ≤ 0.98, no NaN, loops seam-free (Annex E §8).
10. `docs/PERF_REPORT.md` complete per template, including the list of assumptions that still need a real GPU.

## 12. Definition of done (v1.0)

1. `dist/life.html` opens from `file://` and as an artifact, with zero console errors, and reaches the menu in ≤ 3 s and gameplay in ≤ 12 s on the reference desktop (user-verified) and without timeout in headless.
2. New game starts with exactly $100.00; the player can complete the full arc: job → savings → first business → vehicle → property → multiple staffed businesses.
3. All 4 regions, all POIs, 17 jobs with distinct mechanics, 12 business types, property purchase and rental, construction, all vehicle classes, banking, taxes, investments are implemented and reachable through the UI.
4. One ledger; invariant test green; all reports derive from it.
5. All textures and audio are generated by project code at runtime; the repository contains no image, audio or model files.
6. Quality presets Low/Medium/High/Ultra/Auto and all toggles work live; perf HUD present; counter budgets met; perf report filed.
7. Save, load, autosave, export code and import code work, including with storage unavailable.
8. All automated tests green; QA exit criteria met (9.7).
9. `docs/PROJECT_RECORD.md` lists known issues, unverified items, and test results.
