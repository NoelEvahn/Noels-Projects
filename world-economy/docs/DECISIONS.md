The adapter must time-slice expensive changes (texture re-bake, shadow-map resize) behind an "Applying..." indicator. `chunkManager` still reads `settings.graphics.drawDistance` (user value); 3B should read `derived.chunkRadii` (includes governor level 11 `midRadiusDelta`). Renderers with several passes report counters with `perf.recordPass(label, calls, triangles)` and bytes with `MemTracker.addTexture / addRenderTarget`. `Quality.apply(patch)` (MASTER_SPEC 5.11) is idempotent; `subscribe(fn)` gives `{settings, effective, derived, changed, source}`; bus gets `settings:changed` and `quality:changed`.
- **Settings persistence** lives in `render/quality.js` (key `loe.settings`, storage probed with try/catch exactly like `core/save.js`), because `core/save.js` handles game slots and `data/` may not touch `localStorage`. Stored JSON is validated per field; invalid values fall back to defaults.
- **Governor** (`render/governor.js`): levels 0..11 exactly as Annex G 4.1; each step only lowers (enum `lowerOf`, numeric `min`), so a value the user set lower is never raised; resolution floor = user value - 0.3 (never below 0.5). Sliding 120-frame window, p95 > 1.08 T for 45 consecutive frames = down, mean < 0.72 T for 300 = up, 90-frame cooldown, frames > 1 s ignored (hidden tab). Allocation-free per sample.
- **Audio API additions** (additive, gameplay still plays by id only): `Audio.attach({bus, settings, getVehicle, getPlayerPos, getTime})`, `Audio.update(dt)`, `Audio.stats()`, `Audio.prewarm()`, `Audio.music.sting(id)`, `Audio.emitters.add(id, pos) / remove(key)`, `Audio.duck(bus, dB, attack, hold, release)`, `Audio.renderScene(spec, s)` and `Audio.prerenderAll()` (tests), loop handles also have `setPos(pos)`. `data/sounds.js` adds `kind:'music'|'sting'`, `seamWin`, `SOUND_BY_ID`, `REQUIRED_IDS`. `eng.generator` is an internal engine definition (used by `amb.emit.generator`), not a sound id.
- **Audio interpretations** (nearest implementation, interface kept): modal synthesis is additive (one sine per mode with its own T60) instead of a bandpass bank: same spectrum, predictable level. Two-stroke engines (`eng.outboard`, `eng.chainsaw`) fire every revolution (rpm/60 x cyl); the Annex E formula rpm/60 x cyl/2 is the four-stroke case; the test uses `firingHz()`. Engine sub-octave is 0.08 and lump AM <= 0.12, because larger values make the true waveform period 2/f and the autocorrelation fundamental stops matching the firing rate (acceptance rule); the "uneven" twin is therefore mild. Live-graph loop seams use a longer RMS window for beds with slow cycles (`seamWin`: waves 12 s, laps/frogs 8 s, gusts 4 s ...); `amb.emit.lighthouse_horn` (one blast per 30 s) is intermittent, seam N/A. `amb.forest.day` (rms 0.008-0.06, "very low level") and `amb.interior.room` (0.002-0.03, -50 dB room tone) carry their own level ranges. The <= 400 node budget is read as nodes alive at once: measured on a 2 s worst-case slice (beds + engine + music + all six one-shots) = 351; 885 nodes are created over the whole 14 s scene. Music scale membership is checked on the sequencer's note log (no polyphonic transcription); onsets are counted from the audio by spectral flux. Stingers duck the running suite's output by 8 dB rather than the whole music bus (the stinger is on that bus). Beds and music are outside the voice pool (pool = one-shots, engines, spatial loops). HRTF is given to the first 6 spatial voices alive (not re-sorted by distance each frame). Shore proximity uses optional `env.waterDist` (gameplay may supply it); until then beds follow region/district. Vehicle load is estimated from acceleration (the vehicle sim exposes normalised rpm, not throttle). Audio is statically bundled (no dynamic `import()` split yet).
- **Hitch rules for audio:** noise and texture sample data are generated at boot (`Audio.prewarm`), copied into AudioBuffers after init one per frame; bed graphs and emitters start one per update; one-shot pre-renders run one per update and are trimmed to their audible tail (171 one-shots = 20.9 MB cached, cap 24 MB).

## Stage 3B (Opus: visual production)

No CONTRACT CHANGE. Builder signatures (MASTER_SPEC 5.5), `World.*`, `Quality`, harness methods are unchanged; the items below are additive or interpretations.

- **Draft review.** The cancelled draft (`b42ec2b`) was kept where it worked (texture-array library, patch chain, pipeline, sky, lighting/CSM, water, vegetation system, far proxy). Fixed: undeclared `uWaveF` in the water fragment shader (water did not compile), bloom upsample feedback loop (read and write of one target), legacy blockout batches routed to `mat.world`.
- **Texture library layout.** Every `tex.*` set is a layer in one of three texture arrays (tiers H/S/D) holding two maps: albedo (sRGB, alpha = metalness) and data (normal.xy, roughness, AO). This is Annex A 5.3's albedo/normal/ORM set packed into two maps (normal + roughness + AO share one RGBA8). Six facade-module layers were added (`tex.facade_brick/concrete/panel/stucco/office/shop`, one tile = one bay x one storey) for LOD1/LOD2 walls and the far skyline. Medium bakes the S-tier data maps at half size (256) to stay inside its 120 MB library budget; albedo stays 512.
- **Low shader tier.** The Low texture tier compiles a cheaper variant of the world shaders (define `LOE_LOW`): 2-layer terrain splat, albedo-only taps (no normal/roughness/AO fetch), one macro-noise tap. Software GL frame time fell from 600 to 375 ms at V01; on integrated GPUs it is the Low preset's fill-rate lever.
- **Main loop catch-up (main.js hook).** `dtReal` cap 0.1 s -> 0.25 s and at most 8 fixed steps per frame (was 4), so slow frames no longer run the simulation in slow motion. Hidden-tab frames > 1 s are still ignored by the governor.
- **Smoke test holds keys for simulated time.** `test/e2e/smoke.spec.cjs` held W for wall-clock seconds, which made the movement checks a frame-rate test (Annex G: frame rate is never a pass/fail measure here). Keys are now held until 2.5-4 s of simulated time have passed (60 s wall cap). The distance thresholds are unchanged.
- **Windows at night.** Window emission is random per window cell (uv cell of the glass quad or facade module) and masked by the glass channel (metalness 0.9), so LOD0 recessed windows and LOD1/LOD2 facade quads share one lit pattern. Lamp emission is tinted by the vertex tint (red tail lights, green signals); emissive codes >= 251 glow by day as well (signal lights, fire, channel markers).
- **Builders.** Every archetype (210) has a Stage 3 builder; `Builders.blockoutIds()` = 0. Large building builders are generators (`builder.gen`) that yield between faces and every two storeys; the plain call still exists (far proxy, tests). Builder writers are pooled per build so interleaved chunk jobs never share one.
- **Interiors** are appended by their host buildings at LOD0 only (cabins, boathouse, diner, store, fishing hut, lodge, bank, supermarket, garage, warehouse, sawmill). V07 and V14 viewpoints moved inside the boathouse and cabin 1 (`qa/viewpoints.js` gets an optional absolute camera `y`).
- **World decoration placements (MASTER_SPEC 9.1 S3 allowance).** `world/layout/decor.js` (called at the end of `buildWorld`, stored as `World.data.decor`): street lamps every 28 m staggered (cast-iron in Old Town, cobra-head elsewhere), benches, bins, hydrants, meters, bike docks, kiosks, mailboxes, shelters, planters, dumpsters, manholes, utility poles, traffic lights at 70% of city junctions, dock dressing, campsites, the logging yard, mossy boulders and stumps along forest roads, and 47 moored boats along piers and floating docks. Visual only: no colliders, routes unchanged. Light definitions: `decor.lamps` (head position, pool size, ground y) and `decor.fires` (campfires, cabin fireplaces) feed the light pool.
- **Shadow casters (O7).** Detail-ring chunks render LOD0 but cast with a merged LOD1 shadow proxy (layer 1, seen only by the shadow cameras); terrain casts only in the detail ring; props, decor, interiors and vegetation ground cover never cast. Near-ring chunks cast their own LOD1 geometry; mid ring never casts.
- **Chunk batches** are split at 24k vertices per material (each finalises inside one pump slice and uploads < 1 MB); program release: materials are disposed when a quality change alters the shader set (shadow cascades, shader tier), so stale programs do not accumulate (41 programs after Low -> High).
- **Fly-through gating.** The natural-GC ring fly-through is the gating check (0 overruns). The forced-GC run (gc() every 60 frames) is informational with a bound: a forced full collection flushes compiled code, so the next builder call re-compiles inside a slice (an artefact of the measuring mode).
- **Far edge.** The outer skirt now rises gently (5% + a mountain ring over 2.2 km) inland and turns into low headlands sinking into the sea along the southern (ocean) edge, instead of the 30-degree slab visible from Port Calder.

## Visual Fix Round 1 (Sonnet, after the 08:00 review)

No CONTRACT CHANGE. Targets the six user complaints: flat terrain, low-poly look, no life, ugly water, off light and shadows, plain white light.

- **Why it looked washed out (measured, not guessed).** Sun 3.4 (radiance about 1.1) against an environment cube whose sky radiance was about 1.0 gave sun:sky of roughly 1:1, so shadows were filled and everything read flat; the haze colours were grey-beige; the sky was a pale scatter result. Now: sun 7.0 with colour temperature falling with elevation (about 5500 K high, 4300 K at 08:00, 2500 K near the horizon), a captured environment scaled by 0.62 (`uEnv` in the sky shader, the visible dome is unchanged), blue hemisphere light from above and warm earth bounce from below (`uGround`), exposure 0.52 by day (interior 1.15). Shadow:sun is about 1:5 on a clear day. The captured environment has no sun disc.
- **Sky** (`render/sky.js`): the Rayleigh/Mie scatter was replaced by a controlled gradient: horizon = haze colour, zenith = deep blue (greyed by cloud, indigo at dusk), warm sun-side glow whose colour follows the sun's elevation, HDR sun disc. `SKY_FUNCS` is shared with the water shader so the reflection is the same sky. Cloud coverage floor raised from 0.18 to 0.34 so clear days have fair-weather cloud.
- **Fog** is a blue-white haze tinted per region (`REGION_GRADE.fog` are now linear HDR colours), warm toward the sun (broad lobe plus tight core, `uSunFog` = sun colour), cool away from it. Density scale 0.46 (was 0.42), height falloff 0.0032 (was 0.0045) so far terrain gets aerial perspective instead of staying dark.
- **Composite**: split toning (cool shadows, warm highlights by day, moonlit at night, `uTintLo/Hi` from lighting), vibrance (+8% saturation on top of the region grade), a mild S-curve and contrast about perceptual mid grey applied after sRGB encoding. Region grade numbers raised (city +9% warm, saturation 1.06; forest -5%).
- **Night**: window emission now mixes warm tungsten, warm white, cool TV blue and a rare violet; the moon key is blue (0.5, 0.64, 1.0); the hemisphere gets a blue night fill.
- **Water**: own fresnel shading (analytic sky reflection incl. clouds from `SKY_FUNCS`, horizon blended into the haze exactly like the dome), depth colour gradient per profile (ocean turquoise -> blue -> deep navy, lake dark teal, river blue-grey), four scrolling normal octaves fading with distance, sun and moon glitter on the fine normals (HDR sparkles feed bloom), shore foam plus advancing wave lines. The PBR environment reflection is off for water (`envMapIntensity` 0). Not done: planar reflection of terrain and buildings (Annex A lists it for Ultra only; the cost of a second scene pass is not justified under software GL measurements).
- **Terrain / ground**: grass palette less saturated with more dry/bare patches, forest floor browner (needles, litter, less moss), macro variation strength x3.5 with a hue drift, terrain albedo factor 1.28 -> 1.06. Ground cover is scattered on a 1.8 m grid (was 2.5 m) with wildflowers in drifts, clover, forest litter cards, ferns, pebbles and sticks (two small solid instanced meshes). The leaf atlas grew from 4x2 to 4x3 cells (flowers, litter, clover, shrub). Not done: finer terrain cells (the height grid is 4 m, so 2 m cells would only interpolate); relief comes from lighting, macro colour and detail normals.
- **Vegetation**: conifers 1.7x whorls and 3 more fronds per whorl plus a drooping lower layer at LOD0 (about 2.5-3.7k tris, within the Annex A 3-5k target), LOD1 11 whorls; broadleaf crowns 2.6x leaf clusters with smaller cards, two-level limbs with twigs; palms 1.5x fronds; bushes and ferns fuller.
- **Ambient v0 (to be superseded / extended by Stage 4 AI)**: `src/game/ai/ambient.js` (pure JS, no three, no DOM, no allocation per update, typed-array agent pools) and `src/render/ambientViews.js` (instanced views). Cars follow the road-graph lanes (right-hand traffic, lane offsets from the road class), car-following at a 1.4 s headway, signalised junctions (three or more city-class drive edges, 24 s cycle with 1.5 s all-red, stop line 6 m before the node, committed cars clear the junction), turn choice weighted toward straight, spawn ring 45-230 m, despawn 300 m. Pedestrians walk sidewalks (edges with walkW > 0), mostly straight at junctions, random idle stops, walk/idle gait from `art/characters`; spawn 14-120 m. Gulls circle the harbour, marina, cove and lake, crows circle the logging yard and forest (instanced, three wing poses by flap phase). Counts scale with `trafficDensity` and `crowdDensity` (High: about 50 cars at rush hour, about 50 pedestrians; Low 30%) and with the hour (rush peaks 08:00 and 17:30, nights 25-50%) and rain. Cars use LOD0 geometry with spinning instanced wheels inside 50 m, LOD1 beyond; pedestrians use 16 instanced segment meshes per outfit variant inside 32 m and one static instanced figure beyond. Geometry combinations are built one per frame in the background; programs are compiled by the boot prewarm (`renderer.compile` wrapper). No collision with the player, no gameplay, nothing spawns within 14 m of the camera. Stage 4 should reuse `pointAt`, `green` and the lane convention (a->b traffic uses positive offsets, the right-hand side of the edge direction) or replace the file.
- **Test tooling**: `test/visual/shots.cjs` now drains the streaming queue after the settle frames (ground cover, vegetation blocks and ambient geometry are queued by the first frames and were missing from the earlier screenshot set).

## Stage 4 (Sonnet: gameplay and economy)

No CONTRACT CHANGE (`core/contracts.js`, `data/ids.js` untouched). Everything below is additive or a bug fix.

- **Sim layering.** `sim/` imports only `core/` and `data/`. Anything that needs the world (range checks, weather, vehicle in use) goes through `Sim.setServices({near, nearUnit, nearContainer, weather, vehicleInUse, setTime, slope})`, installed by `game/economyLink.js`. With no services every range check passes, so Node tests are place-agnostic. Added `Sim.tickReal(dt)` (fixed-step real seconds, used only to validate `minSeconds` of job tasks) and `createSim({strict})` (re-throw instead of returning `INVALID_ARG`).
- **State layout.** All module state is plain JSON under one `state` object (bank, tax, markets, inventory, skills, needs, jobs, businesses, sites, bizMeta, properties, plots, vehicles, invest, notes, flags, rng, t). `Sim.serialize()` = that plus `ledger`; the three RNG streams (`sim`, `jobs`, `market`) are saved inside it. Round trip is canonical-JSON equal (`test/sim/saveload.sim.mjs`). Key order matters for determinism after load (autoRestock iterates targets), so loads must use `JSON.parse` of a `JSON.stringify` save, which is what `core/save.js` does.
- **Loans are ledger accounts** `loan:<n>` that hold the debt as a negative balance (overdraft = principal). Net worth, the invariant and `bank.takeLoan` caps all fall out of the ledger; no side counters.
- **Reports derive from the ledger.** `reports.pnl` classifies `TX.*` types (revenue / cogs / payroll / opex / tax / other) from `Ledger.totals`; business P&L is therefore cash basis (stock bought is COGS when bought, not when sold). Business tax is 12% of the previous week's positive cash-basis profit, losses carry 4 weeks.
- **Business framework** (`sim/business/core.js`, `hour.js`): one hourly model per `model` field of `data/businesses.js` (`retail`, `vending`, `fishing`, `delivery`, `boatrental`, `logging`, `warehouse`, `rental`). Retail-like types use a `basket` (items per customer) so capacity (customers/hour) and demand (items) stay comparable; `capture` was calibrated with `test/sim/bots/bizBot.mjs` to the Annex D section 7 revenue targets (cafe 1,529 vs 1,450, restaurant 4,370 vs 4,300, vending 105 per machine vs 95, foodstand 532 vs 520, retail 1,974 vs 2,600, supermarket about 12k vs 16k).
- **Shortfalls** become `finance.owed` payables (keyed `account|type`) retried daily; older than 3 days suspends the business (no sales). `biz.close` needs the owner to cover any deficit first (error detail `{deficit}`).
- **Auto-restock** runs daily and, for managed targets, every 3 hours for items below 30% of target. `autoTargets` (default on) re-derives targets daily from the last 3 days of usage x1.5, because targets based only on clipped sales never grow out of a stock-out. Delivery surcharge: 4% manual, 10% unmanaged auto, 0 with an own delivery fleet, -12% with an own staffed warehouse.
- **Vending tiers.** The 5th machine is allowed at tier 1 so `tier.2` (needs 5 units, management L2, $1,200) can be bought; tier 1 is capped at 5 machines, tier 2 at 20.
- **Prices.** Market buy slices are priced after removal, sell slices after adding, both rounded against the trader; the 10,000 round-trip exploit test never profits. Fish allowance 10 kg/day applies only to direct player sales from the `player` container.
- **Job pay** is calibrated for the perfect-play bot at about 1.3x the Annex C table, so the average player (score 0.7, 1.5x task time) lands on the table; `job.ocean.fisherman` trip needs 480 s (a trip per shift). Failed reports skip the `minSeconds` floor. `jobs.estHourly` is a rough estimate (fishing, fisherman and logger are under-estimated).
- **Job controllers** (`game/jobs/`): 17 files extending `JobController`; each task is a chain of shared primitives (`primitives.js`: timingBar, holdRing, tensionBar, sequence/sortLanes, balance, reach/carry/route, choice/inspect/paperwork, gauge, wait) planned in `plans.js`. Controllers run from `Game.update` (once per rendered frame, so Input edges are seen once), read only Input and an `env` {pos, mode, poi, snap}. While a step consumes `interact`, `Game.interact` is suppressed. `bot.js` is the scripted good/bad bot used by tests and `__LOE.bots.run`.
- **Owned vehicles** spawn on `veh:changed` (road vehicle beside the nearest POI, boats at the marina), burn fuel and wear by distance (`veh.use` every 0.5 s), cut the engine on an empty tank. NPC/ambient vehicles that already existed stay drivable (not changed).

- **Balance method.** The measured milestones use the 35% tolerance of Annex D 14, as the acceptance test does. The raw targets cannot be met by the Annex's own typical-business table (paybacks of 22-32 days compound to about 4%/day), so three levers were used, all inside the Annex tolerances: (1) thicker wholesale markets (ingredient targets 4,000 -> 12,000, goods 1,500 -> 6,000, sawmill logs x5), because big buyers (supermarket, restaurants) were paying price impact of up to x2 on staples; (2) retail assortments now carry `refMult` (2.5, was 1.6-2.0) and a `demandMult` that normalises customers per hour by ticket size (an electronics shop made $19-35k a day against a $2,600 target), supermarket refs x1.1-1.25 and capture 0.60 -> 0.40; (3) cafe capture 0.43 -> 0.50 and restaurant 0.66 -> 0.76 (revenue +15%, net +15-24% of the Annex typical, inside +35%).
